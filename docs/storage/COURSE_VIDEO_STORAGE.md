# Course Video Storage (S3-compatible)

Lesson videos are stored in any S3-compatible object store. The backend talks to it
through `StorageService` (`src/modules/storage/storage.service.ts`). The browser uploads
**directly** to the store via a presigned `PUT` URL; the server only stores the object
**key** (plus size/type metadata) on the `lessons.video_url` / `lessons.video_meta` columns.
No video bytes ever transit the API server in the normal path.

The object key is tenant-safe and never embeds raw user input beyond a sanitized extension:

```
tenants/{tenantId}/courses/{courseId}/lessons/{lessonId}/video/{uuid}.{ext}
```

Playback is **private by default**: `getStudio` resolves a stored key into a short-lived
signed `GET` URL. If `S3_PUBLIC_URL` is set (public bucket), it is used as the base URL
instead and no signing occurs.

## Environment variables

| Variable             | Required | Notes |
| -------------------- | -------- | ----- |
| `S3_ENDPOINT`        | yes      | S3 endpoint URL. |
| `S3_REGION`          | yes      | Bucket region (e.g. `us-east-1`). |
| `S3_ACCESS_KEY`      | yes      | Access key / API key. |
| `S3_SECRET_KEY`      | yes      | Secret key / API key secret. |
| `S3_BUCKET`          | yes      | Bucket/container name. |
| `S3_FORCE_PATH_STYLE`| yes      | `true` for MinIO, `false` for most hosted S3. |
| `S3_PUBLIC_URL`      | no       | Public base URL. If set, playback uses public URLs (no signing). |

There is **no code change** to switch providers — only these variables differ.

## Local development (MinIO)

`docker-compose.yml` provides MinIO plus an init container that creates the `titans-local`
bucket and makes it public:

```bash
docker compose up -d minio minio-create-bucket
```

- API: `http://localhost:9000`  ·  Console: `http://localhost:9001`
- Credentials: `minioadmin` / `minioadmin`
- Bucket: `titans-local` (created automatically)

`.env` for local MinIO:

```dotenv
S3_ENDPOINT=http://localhost:9000
S3_REGION=us-east-1
S3_ACCESS_KEY=minioadmin
S3_SECRET_KEY=minioadmin
S3_BUCKET=titans-local
S3_FORCE_PATH_STYLE=true
# S3_PUBLIC_URL=   # leave unset -> private signed GET playback URLs
```

`S3_FORCE_PATH_STYLE=true` is required for MinIO. With it, presigned URLs look like
`http://localhost:9000/titans-local/tenants/...`. The browser PUTs the file straight to
`:9000`; playback uses signed `GET` URLs generated by the API.

The server-side fallback (`POST /admin/courses/lessons/:id/upload`) posts the bytes through
the API when presigned `PUT` is unavailable; it still stores only the key + metadata.

> If `S3_*` are unset, `StorageService` logs a warning and the upload endpoints return
> `400`. Existing lessons with absolute `http(s)` `video_url` values are passed through
> unchanged (legacy hosted links keep working).

## Production (Supabase Storage)

Supabase Storage exposes an S3-compatible API, so the same code works with no changes.
Create a bucket in the Supabase dashboard, then set:

```dotenv
S3_ENDPOINT=https://<project-ref>.supabase.co/storage/v1/s3
S3_REGION=us-east-1
S3_ACCESS_KEY=<project API key>        # anon or service_role key
S3_SECRET_KEY=<project API key secret> # same key / service-role secret
S3_BUCKET=<your-bucket>
S3_FORCE_PATH_STYLE=false
# Optional: if the bucket is public, serve via public URLs instead of signed GETs:
# S3_PUBLIC_URL=https://<project-ref>.supabase.co/storage/v1/object/public/<your-bucket>
```

Notes:
- Use a **service-role** key for writes if you keep the bucket private; an anon key is fine
  for a public bucket.
- Leave `S3_PUBLIC_URL` unset for private (signed) playback, or set it for public delivery.
- Nothing else in the codebase references a specific provider — switching is purely env-driven.

## Cleanup

Deleting a lesson or section (or replacing its video) deletes the underlying object, but only
if no other lesson still references the same key (this guards against duplicate lessons that
share an object).
